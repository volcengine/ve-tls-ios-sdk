# 2.0.2 发布说明

发布日期：2026-10-20。GitHub 版本：[v2.0.2](https://github.com/volcengine/ve-tls-ios-sdk/releases/tag/v2.0.2)。
本版本提供可配置的交付策略、应用自有文件日志可接入的诊断回调，以及持久化隔离与热路径优化。
完整变更列表见 [CHANGELOG](../../CHANGELOG.md)。

## 安装与升级

- SwiftPM：使用 `from: "2.0.2"`，需要固定版本时选择 Exact Version `2.0.2`。
- CocoaPods：可直接通过仓库 Git tag `v2.0.2` 安装。GitHub Release 与 CocoaPods Specs
  发布是独立步骤，只有所用 Specs 源已包含 2.0.2 时才能使用对应版本约束。
- 声明的最低系统保持 iOS 13、Intel macOS 10.15、Apple Silicon macOS 11，要求 Swift 5.8+。

具体安装命令见[安装说明](../getting-started/installation.md)，平台声明和验证范围见
[兼容性](../reference/compatibility.md)。

## 重试与超时

默认策略对齐 Android：不单独限制尝试次数，但受 90 秒重试周期预算约束，首次请求也计入
尝试次数。默认名义退避从 0.5 秒开始，上限 10 秒。整次请求截止默认 90 秒，网络空闲超时
默认 50 秒，每次尝试还受剩余重试预算限制。

开启默认的暂态 HTTP 重试策略时，收到 HTTP 408/499 可以重试；HTTP 400 仅在结构化
`ErrorCode` 为 `ClientCanceled`、`Timeout`、`RequestTimeout` 或 `ConnectionClosed`
时可重试。其他参数、权限和未知 400 错误保持终态处理。服务端 access-log 的 499 不代表
客户端实际收到 HTTP 499，重试和响应丢失仍可能导致重复日志。

升级后应复核显式重试配置与业务超时要求；需要固定尝试次数时配置 `maxAttempts`。
参数、单位和边界见[配置参数](../reference/configuration.md)及[网络与超时](../guides/network-and-timeouts.md)。

## 诊断回调

Swift 和 Objective-C 新增 `diagnosticHandler` 文本回调，复用已有结构化 `onDiagnostic`
及 Core 事件源。SDK 提供等级过滤、独立有界队列、敏感信息裁剪、空值字段省略、重复故障
合并和文本限频；应用可直接将文本写入现有文件 logger。

回调与等级在 `open` 时冻结。应用仍须负责文件路径、轮转和总容量；SDK 不直接创建文件，
不要在诊断回调中将诊断日志再次送入同一个 Producer。
`diagnosticHandler` 从 2.0.2 起提供，2.0.1 及更早版本不包含该接口。
示例见 [Producer 配置](../../Producer/README.md)及[API 参考](../reference/api-and-errors.md)。

## 持久化与内存保留

- 修复旧 owner 在 WAL 接管后的续租、写入、确认和关闭清理竞态，增加随机 owner 标识。
- iOS 复用已有目录独占约束，在实例存活期间持有 Core guard，减少逐条锁文件和读取租约
  的开销；保留线程互斥、心跳和关闭恢复保护。C SDK 公开入口的接管语义保持不变。
- 独立的内存重试保留周期默认关闭，启用后仍受有限 buffer 约束，不能跨进程退出恢复。
  已保留的内存批次在 `close` 时结束，不额外获得最后一次发送机会；跨关闭恢复应使用 WAL。

升级时先关闭旧实例，再用同一持久化目录创建新实例；不要删除活跃实例的 WAL 或锁文件。
详见[持久化与恢复](../guides/persistence-and-recovery.md)。
